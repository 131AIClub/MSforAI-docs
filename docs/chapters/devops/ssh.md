# SSH 远程登录

SSH 已经可以说是一个计算机工程师的计算机所必备的配置了。它主要的用途是**登陆到远程电脑中执行命令**。在今天这个云开发的时代，它几乎是每个程序员每天都要用到的工具。

## 介绍

SSH 叫**安全外壳协议（Secure Shell）**，是一种加密的网络传输协议，可以**在不安全的网络环境下提供安全的传输环境**。早期计算机网络都是明文通信，这导致任何人都可以截获消息，甚至伪造消息。1995年，芬兰学者 **Tatu Ylonen** 设计了 SSH 协议，将登录信息全部加密，成为互联网安全的一个基本解决方案，迅速在全世界获得推广，目前已经成为所有操作系统的标准配置。

> [!NOTE] 协议与实现
> SSH 是一个**协议**，这意味着它只是一种规定，是位于人类思想世界里的东西。而**实现**则是对这套协议的具体实现，例如按照协议的规定实现对应的编码信息，解码信息，加密解密等操作。
协议与实现之间的关系可以用**算法与具体代码之间的关系**来类比。SSH 曾经有很多流行的实现，但今天几乎唯一流行的实现是 **OpenSSH**。它凭借着**免费、开源开放**的优势，打败了所有的商业化选手，
成为了今天 SSH 的主流标准。

## SSH 基本原理

SSH 是一种加密协议，因此在介绍其基本原理之前，我们需要先学习一些**密码学**的基本概念：
- **明文 plaintext**：**信息原先的样子**，发送方想要让接收方收到的实际信息。
- **密文 ciphertext**：**明文被加密之后的样子**，接收者在没有额外线索的情况下，**很难从中还原出明文**。
- **密钥 key**：可以理解成**密文**中的“额外线索”，发送者要用密钥把明文加密成密文，而接收者要用密钥把密文还原为明文。
- **私钥 private key**：私有的密钥，**除了使用者自己之外不能被任何人得知**。
- **公钥 public key**：公共的密钥，**任何人都可以获取**。

> [!TIP] 密钥还是秘钥？yuè 还是 yào？
> 密钥和秘钥都行，但是**计算机行业叫密钥会更主流一些**，这里也更推荐叫密钥。
至于**“钥”**的读音，从语文规范上来说应该读 yuè，但是这么读实在太奇怪了。一个原因是听着像“蜜月”，另一个原因是没有人这么读。所以**人类之间交谈一般会读 yào**。

> [!NOTE] 私钥与公钥
> 你现在可能不能理解为什么会有**私钥**和**公钥**这种东西存在。任何人都能得知公钥，那不是没有秘密属性了吗？并且私钥只有自己能知道，那接收方是无法得知的，接收方没有密钥的信息要怎么解密呢？
先不要着急，**暂时记住它们的定义**。后续在讲解**非对称加密**的时候，你就会理解这种设计的精妙之处了。

### 对称加密

对称加密指的是**加密和解密使用的是同一个密钥**。比较常用的对称加密算法有 AES，DES 等，但本篇文章不对它们的具体原理进行介绍，感兴趣的同学可以自行查阅。

**发送者 sender** 提供**明文 plaintext** 和**密钥 key**。首先使用 key 按照某种算法**加密 plaintext 为密文 ciphertext**，随后发送者通过**网络 network** 发送 ciphertext。接收者与发送者**提前约定好了算法的形式，并且统一了密钥 key**，因此接收者 reciver 可以提供 key 对从网络中接收到的 ciphertext 进行解密，还原回 plaintext，就可以得到发送者实际上想发送的明文内容。

如果出现窃听者或中间人，因为他们并没有密钥 key，因此就算在 network 中截获了 ciphertext，也很难还原为 plaintext。
> [!TIP] 窃听者与中间人
> 窃听者，顾名思义就是在传输时偷偷获取通信者的消息。中间人则指的是拦截发送者的消息，**然后给接收者发送消息**，这导致发送者和接收者不仅无法察觉到中间人的存在（他们认为自己在正常地和对方通信），还有可能接收到被中间人**有意篡改的信息**。常规的加密消息可以防窃听者，但是**很难防住中间人攻击**。解决方案是使用一些更加复杂的身份验证手段，这部分在 SSH 中被包含了。

对称加密的主要优势是效率高、开销小。但是双方需要交换 key 并确认算法的行为并不是很灵活，也并没有那么安全。特别是在多用户情景下，服务器需要保存每个可能会登陆的用户的 key，还要避免这些 key 泄漏。
